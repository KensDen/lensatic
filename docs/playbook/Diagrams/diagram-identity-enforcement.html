IDENTITY-FIRST ENFORCEMENT ARCHITECTURE

Zero-trust control plane for agentic AI — policy decided centrally, enforced at every hop, updated continuously. The flow-and-enforcement companion to the Reference Architecture stack view: that poster says what sits where; this one says how a request is policed end to end.
Identity & Policy Control Plane enterprise-wide, not AI-specific — agents are first-class non-human identities in the same directory, same governance
Identity Provider
Workforce + NHI AuthN. OIDC/SAML, MFA, device trust, continuous access evaluation.
e.g. Entra ID
NHI / ICAM — Agent Identity
Every agent: unique ID, named owner, least privilege, instant revocation. No shared service accounts.
e.g. Entra Agent ID · Agent 365
Token Service (OBO)
On-behalf-of exchange; short-lived, scoped tokens. The agent never outranks its principal.
PIP — Policy Information
Decision context: data classification, device posture, risk signals, session state.
PAP — Policy Administration
Where guardrail and authorization policy is authored — purple-loop findings land here.
PDP — Policy Decision
Central decision point — the non-LLM reference monitor. ABAC/PBAC with obligations; deterministic, auditable.
Continuous-Update Pipeline
Purple loop finds an evasion → PAP updates policy → PDP decides → hot-push to every PEP. No application redeploys. This is the deployment shape of the Gödel mandate (NIST, Jun 2026): no finite guardrail set is universally robust, so the architecture must assume guardrails change continuously — central authoring, distributed enforcement (CSA gateway prescription).

The Lethal Trifecta — every flow must break at least one leg
Leg 1 — Private Data
Broken at the data plane: classification + FGAC obligations decide what the agent can even see.
Leg 2 — Untrusted Content
Broken at the gateway and RAG: input guardrail screening + retrieval provenance before context enters the loop.
Leg 3 — External Comms
Broken at the boundary: MCP signed allow-list + egress filtering — no unlisted destination, ever.
