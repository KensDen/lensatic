Zero Trust for AI Agents

A security framework for deploying autonomous AI agents in the enterprise
“Trust nothing. Verify everything. Assume breach.”
Framework: Anthropic, Zero Trust for AI Agents (eBook, 2026)
Visualization for the Agentic SecOps playbook · controls paraphrased from the eBook
Principles
Never trust, always verify
Every access request is authenticated & authorized regardless of origin: a request from inside the network gets the same scrutiny as one from outside.
Assume breach
Design while expecting compromise. Segment by identity and use fine-grained controls so compromising one system doesn’t grant access to others.
Least privilege → least agency
OWASP’s “least agency” extends least privilege to agents: constrain not just what an agent can access, but what each tool can do, how often, and where.
Design test: “impossible, not tedious”
Friction-only controls (rate limits, extra hops, non-standard ports, SMS MFA) degrade against agentic attackers with unlimited patience and near-zero per-attempt cost. Prefer a control that removes a capability over one that throttles it.
Why now
months → hoursFrontier AI compresses the vulnerability-to-exploit timeline, at a marginal cost measured in dollars.

Capability Matrix: 3 Tiers × 7 Domains
Each tier builds on the one before it: advancing means strengthening controls, not replacing them. “Skip one capability and attackers exploit the gap.”

🔑Identity & authentication
Per-agent cryptographic IDs + short-lived IdP tokens (OAuth 2.0, minutes-expiry). No static API keys.
X.509 certificates with full lifecycle (rotation/revocation); mutual TLS + certificate pinning.
Hardware-backed identity (HSM/TPM) with remote attestation; hardware-bound credentials.
🛂Access control & privilege
RBAC, deny-by-default; static least-privilege roles per agent function.
ABAC with context-aware policies; dynamic privilege adjustment per task.
Continuous authorization; JIT/JEA access with automatic expiration.
📋Observability & auditing
Comprehensive action logs (timestamps, context); request IDs linking actions to triggers.
Immutable audit trails with integrity verification; distributed tracing (OpenTelemetry).
Real-time SIEM streaming + correlation; full input→output provenance chains.
📈Behavioral monitoring & response
Manual baselines; threshold alerts routed through automated first-pass triage.
Learned baselines + statistical anomaly detection; automatic containment & revocation.
ML behavioral analysis + drift detection; orchestrated SOAR response playbooks.
🧪Input & output controls
Input validation + length limits; output filtering for PII/credential patterns.
Attack-pattern filtering; semantic analysis of outputs before delivery.
Constitutional classifiers + spotlighting; human-in-the-loop for high-risk actions.
🛠️Integrity & recovery
Version-controlled configs; documented, tested rollback procedures.
Signed configurations + deployment verification; automated rollback with health checks.
Immutable infrastructure + attestation; self-healing with auto-remediation.
⚖️AI governance
Documented AUP & IR policies; address Shadow AI (LLM use without IT approval).
Formal governance framework with cross-functional stakeholder oversight.
Continuous enforcement with automated compliance checking in deployment pipelines.
Identity comes first: without verifiable identity you can’t enforce access, keep meaningful audit trails, or attribute actions. The Foundation floor has risen: static API keys and SMS MFA no longer qualify, even at the entry tier.
Agentic Threats (OWASP)
1Prompt injection
Direct & indirect. LLMs cannot reliably separate informational context from actionable instructions; the user never sees the indirect payload.
2Tool & resource misuse
MCP tool poisoning, rug-pull tool swaps, tool-chaining exfiltration through trusted binaries, and resource-exhaustion loops.
3Identity & privilege abuse
Unscoped privilege inheritance, confused-deputy relays, and memory-based privilege retention across session boundaries.
4Supply chain & dependencies
Poisoned model weights, malicious MCP servers (~100 found in the wild), and runtime dependency-confusion attacks.
5Memory & context poisoning
RAG / vector-DB poisoning, shared-context attacks in multi-tenant setups, and gradual long-term memory drift.
The floor keeps rising. Expect today’s Advanced tier to become Enterprise standard as the space evolves, and Enterprise to become Foundation. Architect for breach from day one.
Implementation Workflow: 8 Phases
01
Identify requirements
Align security, legal, compliance & business on regulatory and operational goals.
02
Manage supply chain
AI-BOM, OpenSSF Scorecard, cryptographic signing, vendor assessments.
03
Define agent boundaries
Unique ID, approved/prohibited actions, least agency, blast radius.
04
Defend prompt injection
Input isolation, constitutional classifiers, limit the attack surface.
05
Secure tool access
Allow-listing, parameter validation, sandboxing, approval escalation.
06
Protect credentials
Short-lived, hardware-bound, per-agent, JIT, never embedded in code.
07
Safeguard memory
Session isolation, integrity checks at retrieval, retention TTLs.
08
Measure what matters
Dwell time, coverage, explainability: detect a rogue agent within an hour.
Agentic SOAR
Run defensive operations at the speed autonomous threats demand. Put a model at the front of the alert queue for first-pass triage; automate the bookkeeping (evidence, enrichment, correlation, write-ups), and keep humans on the containment, disclosure, and customer-comms decisions. Map detection coverage to MITRE ATT&CK (prioritize lateral movement & credential access), and rehearse a tabletop for five simultaneous incidents, not one.
